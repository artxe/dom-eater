# dom-eater

Error-tolerant AST parsers (HTML, JSX/TS, Razor, Pug). Parser notes are in `.claude/rules/`; differential verification is the `verify-parser` skill.

## Rules
- An unfinished trailing element or attribute ends at the end of the input, so a parse of the text before an editor's cursor ends on the element being typed. Node shapes are public API: changing one is a breaking release.
- Error messages are sentences.
- Modules: one `export default` per file, a function or constant named by the file (or by its folder, for `index.js`), imported under that name; helpers only one function uses stay private in its file. A folder is a function with helpers of its own, never just `index.js`. Each parser lives in its entry point's folder (`src/parse_html/`, `parse_jsx/`, `parse_pug/`, `parse_razor/`); `parse_script.js` and `parse_razor_component.js` call the JSX and Razor cores; `src/script_scanner/` is the scanner HTML, JSX and Pug share; `src` itself holds only what all parsers use. Deeper down, a module lives in the folder of its only importer, else in the folder its importers share, so other parsers import only files directly in a parser or scanner folder. Lint rejects named exports in `src`.
- Tests: one `test/<src file name>.test.js` per exported function, including its framework, README and reference parser cases; shared helpers in `test/helpers.js`, the TypeScript comparison in `test/typescript_ranges.js`. `test/readme.test.js` type checks every top level ```ts block of the README and runs the parser of each block that a ```json block follows, so the shown output is the real one; it counts the blocks it checked against the fences so a block can never drop out unnoticed. Seeded fuzzing and reference-parser differentials: `test/fuzz/<src file name>.test.js` per exported function, their generators and references in `test/fuzz/*.js` (the Razor one in `test/fuzz/razor/`); large runs are in the `verify-parser` skill.
- Names: functions are verbs (`parse_*`, `skip_*` returning the index after, `is_*`/`has_*` for booleans, `create_*` for new state) or name the value they return (`*_end`, `*_start`, `previous_word`); constants are nouns (`*_regex`, `*_pattern` for regex source strings, plural Sets). Ports keep upstream names (pug-lexer rules, Razor's `accept_until`, `balance`).
- `public.d.ts` holds the published types, which `pnpm dts` re-exports from `types/index.d.ts` so callers import them from `dom-eater` itself; `private.d.ts` holds the unpublished parser-internal types, so `files` lists the declarations the entry reaches instead of all of `types/`. `public.d.ts` must not import from `src` or `private.d.ts` (consumers would get `any`). They are the only hand-written `.d.ts`; any other one outside `types/` is stale tsc output to delete.
- `tsc` is TypeScript 7 and must pass. The `typescript` dependency stays 6 because `test/typescript_ranges.js` needs that API, not to check with it. `tsconfig.build.json` checks `src` as ES2020 (`lib` and `target`: newer APIs and regex flags `d`/`v` fail) with no Node types and full `.d.ts` checks. Lint's `no-restricted-syntax` holds the syntax to ES2020 (no `&&=`/`??=`/`||=`, no static blocks).
- Comments: JSDoc types and casts only. Description and `@example` prose only on the entry points `src/index.js` exports and in `public.d.ts`.
- Not enforced by lint: ABC order by code unit (imports by first binding, top-level constants then functions, object keys, list entries, test titles) unless the order carries meaning.
- The package is an ES module only, with no CommonJS build. `pnpm dts` appends the `public.d.ts` re-export to `types/index.d.ts`; `types/` is the only build output and is gitignored. `test/package.test.js` bounds the published file list.
